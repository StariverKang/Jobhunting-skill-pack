# Jobhunting Skill Pack

一套面向中文求职简历的 Agent Skills：先做全局审查与定位，再精修保留经历，最后针对目标公司与 JD 生成简历顶部的四条自我评价。

## 一键安装

默认安装到 `~/.agents/skills`：

```bash
curl -fsSL https://raw.githubusercontent.com/StariverKang/Jobhunting-skill-pack/main/install.sh | bash
```

也可以克隆后本地安装：

```bash
git clone https://github.com/StariverKang/Jobhunting-skill-pack.git
cd Jobhunting-skill-pack
./install.sh
```

其他安装目标：

```bash
./install.sh --claude              # ~/.claude/skills
./install.sh --codex               # ~/.codex/skills
./install.sh --target /path/to/skills
```

若目标目录已有同名 Skill，安装器会先将旧目录备份到目标目录下的 `.jobhunting-skill-pack-backups/<时间戳>/`，再安装新版本。

## 三个 Skill 的位置

| Skill | 仓库位置 | 默认安装位置 | 在整套方法中的位置 |
|---|---|---|---|
| `consultant-style-resume-audit` | `skills/consultant-style-resume-audit` | `~/.agents/skills/consultant-style-resume-audit` | 架构层：判断候选人阶段、目标叙事、证据取舍、经历顺序与修改优先级 |
| `cv-experience-refinement` | `skills/cv-experience-refinement` | `~/.agents/skills/cv-experience-refinement` | 正文层：把选中的单段经历改写为双层“总—分”结构 |
| `bio-for-cv` | `skills/bio-for-cv` | `~/.agents/skills/bio-for-cv` | 首屏层：结合当前履历、目标公司和 JD，生成四条候选人中心的自我评价 |

安装到 Claude、Codex 或自定义目录时，只需将表中的默认根目录替换为对应目标目录。

## 方法论总览

### 1. 简历是一套面向目标岗位的证据系统

简历不是经历存档，也不是把所有亮点平均铺开。整套方法把简历拆为四层：

1. **叙事**：候选人是谁，沿什么路径成长，下一步适合解决什么问题；
2. **证据**：哪些经历、项目、作品与结果能够证明这条叙事；
3. **翻译**：怎样把来源行业的动作转换为目标 HR 和业务面试官熟悉的语言；
4. **呈现**：如何用首屏摘要、排序、层级、标题和篇幅，让最重要的信息先被看到。

稳定的处理顺序是：

`当前事实 → 候选人阶段 → 目标叙事 → 证据取舍 → 经历精修 → JD 定向摘要 → 人工核对`

### 2. 事实优先级与边界

出现冲突时，采用以下优先级：

`用户当前说明 > 当前事实素材 > 当前简历 > 当前 JD > 旧版简历或建议稿`

每个可投递表述都应能回到明确来源。不同经历的事实不能拼接；公司业务、JD 职责和写作建议不能倒写成候选人的既往事实。允许做行业化翻译、能力抽象和方法论命名，但必须区分：

- **既往事实**：材料中有动作、工具、交付或结果支持；
- **能力抽象**：对已发生动作的专业化概括；
- **前瞻方法**：基于相邻能力可采用的方法，不能写成已经实践过；
- **待确认项**：数字、日期、Title、专有系统实操或因果结果等仍需本人核对的内容。

### 3. 先决定“讲什么”，再决定“怎么写”

全局审查先用两个互相独立的维度路由：

- 候选人阶段：`起步型 / 成长型 / 冲刺型`；
- 材料形态：履历总量 `过少 / 适中 / 过多`，单条密度 `单薄 / 适中 / 丰富 / 混合`。

随后把经历标记为：

- **支柱**：直接证明目标岗位的核心问题；
- **证明**：补充另一项关键能力或成长节点；
- **补充**：提供背景或独立信号，轻量呈现；
- **删除**：重复、跑题或理解成本高于收益。

这一步解决跨经历的选择、排序和篇幅分配。不能用固定经历数或固定字数代替判断，也不能让每段经历获得相同篇幅。

### 4. 单段经历采用双层“总—分”

进入精修的经历按两层组织：

- 第一层“总”：业务或项目是什么、服务谁、候选人的范围与目标是什么；
- 第一层“分”：2–4 个互不重复的能力主题；
- 第二层“总—分”：每个主题内部写清场景、约束、判断、动作链、方法或工具、交付与结果。

专业经历的最小闭环是：

`问题/前置条件 + 约束与判断 + 方法/工具链 + 动作链 + 交付/结果 + 影响`

工具和术语必须与准确动词、对象及交付相连。没有因果证据时，不把“参与”夸大为“带来”。

### 5. 首屏摘要不是经历复述，也不是求职信

顶部四条摘要共同回答：

1. 候选人是谁，属于什么职业画像；
2. 最核心的硬技能和完整任务链是什么；
3. 差异化的第二能力域或判断方式是什么；
4. 哪组既有能力对目标公司和 JD 最有价值。

公司与 JD 负责决定证据优先级和专业语言，不应成为正文主语。摘要不写“定位某岗位”“适配某团队”，不重复具体经历，不把公司宣传语写成候选人能力。

### 6. 招聘方可读性与专业密度同时成立

首句和总述降低理解成本，能力分点承担专业密度。陌生机构、业务模型和缩写先翻译成人话；方法、技术、编程语言、查询语言、软件、平台、指标和交付物必须使用各自准确的谓词，不能统一包装成“工具”或“方法”。

个性也必须由行为支撑。“网感”“产品 sense”“数据敏感度”等表达只有在能接上选题判断、需求转化、数据复盘或产品取舍时才成立。

### 7. 结构校验不替代事实核验

三个 Skill 都把结构检查与事实判断分开：脚本可以检查章节、长度、模式、禁用表达和固定格式，但不能证明某个数字、结果或项目归属真实。最终交付前仍需候选人核对事实，并在 DOCX/PDF 场景检查渲染、分页和首屏信息密度。

## 三个 Skill 如何协同

```mermaid
flowchart LR
    A["当前简历、事实素材、目标方向"] --> B["consultant-style-resume-audit\n定阶段、叙事、取舍和优先级"]
    B --> C["精修交接包\n范围、模式、主题、事实与禁写边界"]
    C --> D["cv-experience-refinement\n重写支柱与证明经历"]
    D --> E["更新后的事实型经历正文"]
    E --> F["bio-for-cv\n结合当前公司与 JD 生成四条摘要"]
    F --> G["人工事实核对与版面检查"]
    G --> H["目标岗位版本"]
```

关键边界：

- 审查 Skill 决定跨经历的取舍与顺序，不替代单段深度改写；
- 经历精修 Skill 只处理指定经历，不自行推翻全局叙事，也不跨项目拼事实；
- 顶部摘要 Skill 使用更新后的履历证据，不承担整份简历重写；
- 三者共享事实边界，但分别负责架构层、正文层和首屏层。

## 应用模式

### 模式 A：从旧简历到目标版本

1. 用 `consultant-style-resume-audit` 生成分档审查、P0/P1/P2、经历取舍和精修交接包；
2. 将交接包中的支柱/证明经历交给 `cv-experience-refinement`；
3. 人工确认增补项并更新简历正文；
4. 用 `bio-for-cv` 对目标公司和 JD 生成四条首屏摘要；
5. 做事实、版面和五秒扫描检查。

### 模式 B：已有稳定主版本，只做 JD 定向

如果经历正文已经真实、完整且结构稳定，可直接使用 `bio-for-cv`。当新 JD 要求的核心能力在正文中难以被快速识别时，再回到审查与经历精修，而不是把缺失证据硬塞进摘要。

### 模式 C：只修一段经历

已明确保留范围时，可直接调用 `cv-experience-refinement`。有完整事实时使用 `final`；动作可识别但方法、数据或结果细节不完整时使用 `enhanced-draft`；连两个可解释动作都无法识别时使用 `incomplete` 并补充素材。

### 模式 D：经历太多或方向分散

必须先用审查 Skill 做目标叙事、同生态位去重和容量分配。不要先把所有经历写长，否则只会放大噪声。

### 模式 E：不同岗位维护多个版本

保留一份经过事实核对的母版经历库。每个目标岗位重新执行“审查取舍 → 主题排序 → 顶部摘要”，而不是修改底层事实。目标变化时，叙事、篇幅和语言可以变化，事实归属不能变化。

## 调用示例

完整流程：

```text
请先使用 consultant-style-resume-audit 审查这份简历与目标 JD，输出经历取舍和精修交接包；再按交接包使用 cv-experience-refinement 处理首批经历；我核对事实后，使用 bio-for-cv 生成四条简历顶部自我评价。
```

只做经历精修：

```text
请使用 cv-experience-refinement，将以下经历按双层“总—分”结构改写。保留事实归属；未确认的方法、数据或结果按 enhanced-draft 标记，不补造精确数字。
```

只做 JD 摘要：

```text
请使用 bio-for-cv，根据当前简历、目标公司和 JD 生成四条候选人中心的中文自我评价。
```

## 校验

```bash
./scripts/test_pack.sh
```

该命令会在临时目录验证统一安装，并运行三个 Skill 自带的回归测试。

## 隐私与发布边界

本仓库不包含候选人简历、原始个人材料、私人消息、真实测试输出或可识别个人信息。示例应保持匿名，不得把用户材料写入 `skills/`。
