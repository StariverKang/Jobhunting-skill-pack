## 1. 目标

把自我评价当作整份简历的候选人能力索引，而不是求职意向、JD 摘要或性格宣言。HR 应能在数秒内看出候选人的专业/职业背景与领域、最强的两项能力、完成工作的方式、能够形成的专业交付，以及后文哪类经历可以验证。简历上文已经展示的院校、学位和学历不属于新信息，默认不在这里重复。

## 2. 事实与来源优先级

候选人事实按以下顺序处理：

1. 用户在当前对话中明确确认的事实；
2. 用户指定为最新版的履历或素材；
3. 当前提供但未标为最新版的材料；
4. 旧版简历、旧摘要或第三方转述，仅作冲突提示。

同一事实出现日期、职位、指标或职责冲突时停止使用，最多提出三项澄清问题。不要自行挑选更有利的版本。

## 3. 每次刷新公司研究

按以下顺序研究，不把时效性信息固化进 Skill：

1. 公司官方职位页和该岗位的当前 JD；
2. 公司官网的产品、业务、客户、市场与 About 页面；
3. 官方新闻、博客、公告或投资者资料；
4. 可靠招聘平台上的同公司同职能岗位；
5. 权威行业媒体、研究机构或监管披露。

记录页面标题、URL、发布日期或访问日期。区分“公司明确陈述”“JD 明确要求”和“根据多项来源作出的推断”。职位已下架、公司同名或来源互相矛盾时，要求用户提供官方材料。

公司与 JD 研究承担“选择器”作用，用来决定能力排序、术语颗粒度与信息取舍，并确定第四条应突出哪组既有能力与业务价值。研究结论不直接复述，不在正文中出现公司规模、团队名称、岗位标题、实习属性或“面向该团队”的解释。定制既体现在四条的取舍与顺序，也体现在第四条所选择的能力交集，但不通过复述目标来证明匹配。

## 4. 提炼岗位需求

先写内部工作稿，不展示给用户：

- 岗位核心目标：用一句话说明这个岗位最终要推动什么业务结果；
- 3–5 个能力词：优先选择多次出现、属于必备条件或直接承担核心职责的词；
- 公司特定需要：说明这些能力将服务哪个产品、用户、市场或增长阶段；
- 排除项：只有文化口号、通用素质或无法对应候选人证据的词。

先消除语义歧义。结合上下文判断缩写和工具名，例如设计软件列表中的 `AI` 通常指 Adobe Illustrator，不能自动匹配为人工智能经验；无法确认时查询来源或询问用户。

### 校准目标行业读者的语言

先判断目标行业、职能与首轮阅读者通常熟悉的信息，再建立四层表达表：

1. **目标行业原生词**：该行业 HR 和业务团队通常理解的缩写、指标、平台与业务环节，可自然使用，不必全部翻译成大白话。
2. **相邻行业可迁移词**：目标读者可能理解一部分，首次出现时补充行业属性或业务等价含义。
3. **来源行业专有词**：目标读者大概率陌生，先说明实体是什么，再把动作与结果翻译成目标行业能识别的能力。
4. **招聘语感与自然能力语言**：“网感好、产品sense、用户sense、商业化意识、数据敏感度、闭环意识、兼具业务视角、用户视角与产品视角”等短语能快速建立人才印象，可与行业术语混合使用；但必须在同条中由具体任务、判断或工作方式支撑，不能成为空泛性格标签。

翻译时保留事实身份，不把行业转换写成经历转换。例如：

- 投互联网或 AI 岗时，不只写陌生平台名称，而写 `某平台（Web3 交易所）` 或 `某产品（Web3 钱包）`；可保留互联网读者熟悉的用户增长、内容营销、转化与数据复盘等术语。
- 投 Web3 岗时，可以直接使用交易所、钱包、链上数据、Listing、空投等行业词；来自传统互联网的增长经历则要说明具体渠道、用户动作与结果，不能假定 Web3 HR 熟悉所有广告或电商指标。
- 投投资、制造、教育等其他行业时，沿用目标行业常用的研究、项目、客户或交付语言，并把互联网/Web3 黑话翻译为产品、用户、收入、效率、风险或市场结果。

不要过度翻译目标行业本身的常用词，也不要为了显得专业而保留目标读者无法解码的组织名、产品模块或缩写。必要时采用 `专有名词（行业属性/普通业务含义）` 的首次定义，后文再使用简称。

### 专业化增益的三层授权

专业表达不要求所有术语逐字出现在原简历。先判断表述层级：

1. **既往事实**：公司、职位、项目、工具实操、具体指标、结果与证书，必须有来源，使用过去式或事实句。
2. **能力抽象**：已有行为链与行业标准方法的核心步骤相符时，允许用标准术语重新命名。例如节点拆解与风险跟踪可抽象为 `PMO/WBS/RAID` 思路，周期性指标复盘可抽象为 `KPI Tree/WBR/MBR`，竞品对比可抽象为 `Benchmark`，转化环节分析可抽象为 `Funnel`。无需追问原简历是否写过这些词。
3. **前瞻方法**：候选人只有相邻技能、目标岗位又高度依赖某方法时，可以写“可用、可迁移、可围绕、可按……框架”支持目标任务；不要写“曾使用、熟练使用、主导过”或为该方法补造历史结果。

每组四条选择 5–9 个专业锚点，第二、三条至少各有一个；再从证据中选择 1–3 个自然能力表达，让 HR 同时看到专业方法与人的工作感觉。关键术语覆盖是必须项，但术语数量不是专业度评分：至少一条用 2–4 个同类能力域或术语建立能力版图，至少一条说明其原理、应用、交付或能力边界。优先组合 `准确谓词 + 方法/技术/语言/工具 + 处理对象 + 指标/交付物`，或 `自然能力表达 + 可观察行为 + 判断/价值`。同一条通常放 1–3 个专业锚点，同类词可共享谓词；跨类别词必须分别说明，例如“了解NLP、LLM与RAG等技术原理，熟悉CoT等推理方法，具备Agent/Workflow的基础设计能力”。具体词组从 [lexicon.md](lexicon.md) 的相关子组轮换选择，也可基于公司和 JD 研究补充同等级术语；不得因列表顺序固定复用同一批词，也不得因词库丰富就强行塞满缩写。

### 关键词语义类型与谓词匹配

在进入正文前，为每个专业锚点记录 `关键词｜语义类别｜证据强度｜可用谓词｜处理对象｜实际产出`。至少区分：

| 语义类别 | 例子 | 自然谓词与写法 |
| --- | --- | --- |
| 能力域 | 数据分析、内容运营、行业研究 | `具备、兼具、能力扎实` |
| 方法 | Prompt Engineering、Benchmark、Funnel、A/B Testing | `掌握、运用、采用……方法` |
| AI 技术或架构 | RAG、LLM、NLP | `理解原理与边界、能够应用于具体任务` |
| 编程语言 | Python、JavaScript | `掌握基础语法、使用……编写/调用/处理` |
| 查询语言 | SQL | `编写 SQL 查询、使用 SQL 处理结构化数据` |
| 软件工具 | Excel、SPSS、Tableau | `使用……整理/分析/可视化数据` |
| 框架、库与接口 | FastAPI、React、模型 API | `使用 FastAPI 搭建接口、基于 React 开发组件、调用模型 API` |
| 平台 | TikTok、Instagram、Google Ads、Meta Ads | `运营、配置、投放、分析平台数据` |
| 指标 | CTR、CVR、ROI、Retention | `追踪、分析、围绕……复盘` |
| 质量机制 | Human-in-the-loop、交叉验证 | `设置、保留、通过……校验` |
| 交付物 | 深度报告、内容 brief、SOP、Dashboard | `撰写、形成、沉淀、输出` |

裸枚举只允许同类项共享同一谓词，例如“使用 Excel、SPSS 整理数据”成立；“熟悉 Prompt、RAG、SQL、Python 等工具”不成立，因为四项分别属于方法、AI 技术、查询语言与编程语言。跨类别时拆成独立动作，推荐写成 `掌握 Prompt Engineering，理解 RAG 的检索增强机制，能够编写 SQL 查询并用 Python 处理数据`。

`Prompt` 只有在指一段具体提示词文本时才作为名词使用；表达能力或方法时写 `Prompt Engineering`、提示词设计或提示优化。不得为了节省字数把类别删除，再用“工具、技术、能力”等宽泛名词兜底。

不要把“术语没有逐字证据”与“事实造假”混为一谈。正常的行业化翻译和方法抽象属于授权范围；只有新造任职、项目、工具实操、数据、结果或证书才越过事实边界。

## 5. 处理不完全匹配

把匹配结果分成三类：

- **直接匹配**：候选人做过 JD 所述任务，并有具体动作或结果；
- **可迁移能力**：候选人没有同名工具或行业经历，但完成过相邻流程或更完整的实际交付；
- **真实能力缺口**：没有事实支持某项技能、经历、具体工具实操或历史结果，不能把它写成既往事实；若存在相邻行为，只能按“能力抽象/前瞻方法”表达，否则省略；
- **投递条件**：年级、毕业时间、学历层级、城市、线下面试或办公、到岗日期、每周出勤、实习时长、签证身份、转正意愿等招聘流程条件。

优先把直接匹配和高价值可迁移能力写入摘要，突出能解决岗位核心目标的稀缺组合、独立作品与完整闭环。不要在四条中主动罗列能力缺口，但不得把可迁移能力写成已经精通目标工具或目标行业。

### 投递条件不阻塞自我评价

本 Skill 的任务是提高候选人在简历首屏的可读性与岗位适配表达，不是替 HR 审查投递资格。求职条件存在沟通、调整和例外空间，默认用户有权决定是否投递。因此：

- 不主动核验、追问或质疑年级、毕业时间、学历层级、年龄、城市、到岗、线下安排、每周出勤、实习时长、签证身份和转正意愿。
- 不根据入学日期自行推断年级，也不把“未提供”解释成“不满足”；不因 JD 使用“必须、仅限、至少”等措辞改变这一规则。
- 不把投递条件放入证据矩阵，不参与匹配评分，不阻塞四条摘要，也不输出“满足条件后再投”“不建议投递”等资格结论。
- 已有一份明确履历时直接作为当前输入，不例行追问是否存在更新版本；只有同时存在多个候选版本、用户提到新版但未提供，或拟采用的核心事实互相冲突时才澄清。
- 只有用户明确要求进行资格评估、填写申请表或投递备注，或要求在其他文案中表达到岗安排时，才询问对应条件；该任务与四条能力摘要分开处理。

保持积极但真实的定位：不因为部分 JD 能力没有直接证据就降低整段语气。用直接匹配与可迁移能力构建最强候选人定义，省略不相关缺口；不得虚构，但也不得使用“虽然、仅、勉强、可以试试、可能符合”等替 HR 自我淘汰的措辞。

## 6. 建立证据矩阵

先给每段公司、项目、比赛或独立作品分配唯一 `experience_id`。为每个候选表述记录：`表述｜表达层级｜experience_id｜JD 优先级｜公司相关性｜履历证据｜证据强度｜差异化｜目标行业译法`。表达层级取“既往事实、能力抽象、前瞻方法”之一；能力抽象和前瞻方法以相邻行为为证据，不要求原词逐字出现。

评分标准：

- JD 优先级 0–3：3 为核心目标、必备项或反复出现；2 为直接职责；1 为加分项；0 为无关。
- 证据强度 0–3：3 为具体动作加量化结果或可核验作品；2 为具体项目、动作、工具或业务结果；1 为自述、工具清单或无场景证书；0 为无证据。
- 公司相关性 0–2：2 为直接服务公司当前产品、用户或市场；1 为同赛道通用；0 为泛化。
- 差异化 0–2：2 为稀缺组合、显著结果或独立作品；1 为具体但常见；0 为空泛。

排序分数为：`3×JD 优先级 + 3×证据强度 + 2×公司相关性 + 差异化`。既往事实和能力抽象的支撑强度低于 2 时不得进入结果；前瞻方法需要至少一项相邻行为，并使用能力态或将来态表达。同义表述只保留得分最高的一条。

个人特质和自然能力语言必须由行为反推。例如，多地区英文内容协作可支持“跨文化协作”，持续推进多个参与方并按期交付可支持“跨团队推进”，长期跟踪平台热点并将其转化为选题或传播动作可支持“网感好”，能在用户需求、业务目标与实施成本之间做取舍可支持“产品sense”，能把反馈、数据和场景转化为需求或策略可支持“用户sense”。单纯自称不能作为证据。

## 7. 保持履历独立并提炼共性

每个动作、工具、数字、奖项和结果都是原子事实，默认只归属于一个 `experience_id`。写作时遵守：

- 不把不同公司、项目或比赛写成同一段工作、同一项目阶段、因果链或时间先后链。
- 不用含混的“并、同时、因此、从而、继而”连接互不相关的履历事实。
- 同一条引用多段经历时，使用“分别”“另在”“另一项经历”“独立项目中”等边界词，并用分号或完整分句隔开。
- 让每个数字、奖项和结果紧邻其所属经历，避免一个谓语或结果看似同时修饰两段经历。
- 只有来源明确证明关系时，才能写“基于前述经验”“随后”“推动”“因此”等逻辑或时序连接。

跨经历共性必须至少由两个独立 `experience_id` 中相同的行为模式或能力证据支持。先分别说明证据，再在能力层抽象；只合并能力判断，不合并各自的业务结果。

证据矩阵内部可以分别记录 Web3 交易所分析与独立数学建模项目，共同支持“数据分析与结构化研究能力”。四条正文只写能力结论，例如 `具备数据分析与结构化研究能力，能够完成竞品拆解、指标分析、问题建模与敏感性分析`，不写具体项目、比赛或获奖结果。

## 8. 四点固定漏斗

1. **职业定位与复合画像**：把候选人的专业/学科或职业背景、相关行业实践与两三项核心能力翻译成目标行业 HR 可识别的职业身份。在简历首屏场景只写“金融学背景”等有关专业，不写“某某大学金融学背景”；院校已由上方教育经历承担信号。这里的“定位”是 HR 对候选人的专业归类，不是候选人的求职意向；不得写“定位某实习”“职业方向聚焦某岗位”。
2. **核心硬技能闭环**：说明候选人如何使用研究方法、业务框架、数据工具或运营方法完成一组相互衔接的任务，并形成报告、判断、方案、增长结果或决策依据。
3. **差异化第二能力域**：展开技术理解、定量分析、产品视角、内容能力、语言能力等另一组硬能力，说明它如何扩展候选人的观察维度与判断质量。
4. **公司与 JD 适配能力**：找出公司需求、JD 核心任务与候选人既有能力的最强交集，从研究交付、长文本写作、英文表达、结构化沟通、跨团队推进、数据敏感度、AI 实操或专业方法中选择一组，写成候选人能够完成的任务、形成的交付和带来的业务价值。不得写成“面向某团队”“适配某岗位”或公司/JD说明。

四条共同形成“职业画像 → 核心闭环 → 复合判断 → 定向价值”的阅读路径，全部以候选人为主语。JD 决定哪些能力排在前面以及第四条突出哪个交集；删除公司名和 JD 原文后，四条仍应是一份完整、丰富且成立的自我评价。不要重复堆砌同一关键词，也不要把第四条降格成“可将经验用于目标工作”。

## 9. 信息颗粒度

每条不是短标签，而是一个完整的信息单元。每条硬下限 55、硬上限 120 个非空白字符，四条合计至少 280 个；证据充分时以每条 70–105 字为目标。长度必须来自方法、对象、动作、工具、判断和交付的增加，不能来自同义形容词或 JD 复述。

证据层和表达层必须分开：证据矩阵回答“凭什么这样说”，最终四条只回答“候选人会什么、能做什么”。任何一条若主要复述公司、项目、比赛、时间、奖项、名次、动作和结果，即使事实准确也不合格；应把事实归纳为稳定能力，再写成可承担任务、方法与价值。具体组合优先读取 [patterns.md](patterns.md)。

优先采用以下组合：

- `能力主题 + 谓语 + 具体技能/方法 + 处理对象 + 产出或结果`；
- `背景与熟悉领域 + 两三项复合能力 + 观察或判断维度`；
- `有证据的特质 + 体现该特质的行为 + 对岗位的价值`；
- `高价值综合能力 + 稳定工作方式 + 可持续形成的交付与质量标准`。

正文不用冒号把能力标签和说明句硬拆开。专业度不等于术语密度；若某条已有清晰的能力主题、判断过程和价值，可用“网感好”“产品sense”“兼具业务视角、用户视角与产品视角”等自然语言代替一组没有增益的框架词。需要总分层次时，先把中心能力写成主语或谓语的一部分，再用“能够、熟悉、善于、并通过”等连接词自然展开；需要区分不同能力维度时可用分号或完整分句。不要用破折号连接缺少共同中心词的名词片段，也不要让后一个并列项突然改变前文的句法结构。每条通常包含两到四个相互关联的能力组件。技能名称要具体到研究方法、分析工具、业务环节、平台或交付物，避免只写“产品能力强”“数据敏感”“懂 AI”。颗粒度增加不等于罗列：没有共同能力主题的内容应拆开；独立事实只在内部证据矩阵中保留来源边界，正文提炼其共同支持的能力。

## 10. 压缩规则

- 使用普通业务语言，删除陌生组织术语、模块名和自造概念。
- 优先保留“能力 + 场景/对象/结果”，删除“本人”“具备良好的”“拥有较强的”等空壳前缀。
- 使用 JD 与目标行业自然的关键词；允许加入能命名既有动作或延展相邻能力的方法术语，不复制长句，不为 ATS 堆词。
- 简历上方已有教育经历时，把“上海财经大学金融学背景”压缩为“金融学背景”；院校名、学位和学历层级不与后文争夺字数。
- 保留有证据的招聘语感，例如“网感好，能够捕捉平台热点与用户情绪”或“兼具业务视角、用户视角与产品视角，能够在价值、体验与实施成本之间做取舍”；不要为显得严谨而全部改成抽象术语。
- 压缩的是冗余信息，不是术语本身。不得截断英文单词、把动作名词改成含义不同的名词，或用中英混搭制造假缩写；`Copywriting` 可写为“英文文案撰写”，不能写为“英文 Copy”。
- 除非证据足够，不使用“精通”“专家”“深度理解”“主导”等高强度词。
- 公司事实只能说明适配对象，不能冒充候选人的工作事实。
- 删除候选人历史中的公司名、项目名、比赛名、奖项、名次、排名、时间和结果，只保留这些事实共同支持的能力结论。目标公司和 JD 中的业务对象不属于此删除项。
- 删除投递说明与预期概括，包括“定位、面向、适配、匹配、目标岗位、实习方向、可将经验用于/迁移至、快速进入某场景”。目标公司和 JD 只用于内部选择能力，不直接进入四条正文。
- 压缩前先检查四条是否分别承担画像、核心闭环、复合判断和综合交付；不得为了避开禁词而删掉方法、对象、工具、产出和判断依据。

## 11. 失败与恢复

- 缺少 JD、公司岗位或履历：一次最多追问三项，不先给草稿。
- 履历过薄：追问可核验的项目、动作、作品或结果；仍不足时说明无法安全生成。
- 无法联网：要求官方 JD、官网资料或用户认可的公开来源。
- 信息冲突：列出最小冲突点并要求确认，不自行合并。
- 发现年级、到岗、排班、地点或实习时长未确认：直接忽略这些投递条件并继续生成，不触发澄清。
- 已有单一履历文件但不确定是否最新：直接使用；除非存在新版线索、多个版本或核心事实冲突，不追问。
- 用户要求补造任职、项目、数据或结果：不采用这些可核验假事实，直接给出行业化翻译、能力抽象或前瞻方法的替代表述，不进行道德说教。
- 第二、三条读起来像单段履历摘要：隐藏公司与时间，重新提炼能力主题、处理对象、可完成任务链、方法工具和专业交付，用信息完整度恢复可信度，不把具体经历加回正文。
- 第一条或其他任一条出现具体比赛、奖项、名次、项目或历史公司：删除该经历叙事，回到证据矩阵提炼其支持的能力域、方法和可承担任务。
- 第一条重复出现院校名、学位或学历层级：判定为简历上下文去重失败，只保留与岗位有关的专业/学科背景或直接从职业能力开头。
- 四条充满缩写、框架和指标，却看不出候选人的内容判断、用户理解、产品取舍或工作方式：删除低增益术语，用有行为支撑的自然能力语言恢复人才画像。
- 出现“定位某实习”“面向某团队”“适配某岗位”“可将经验用于目标工作”：说明 JD 泄漏进了正文。删除目标组织与预期职责，改写为候选人已经具备的能力、任务链和交付方式。
- 四条明显变短、句式单调或只剩能力标签：不要继续删词；回到证据矩阵补入处理对象、方法工具、关键动作、判断维度、交付物和质量控制，直到满足 55–120 字单条与 280 字总量要求。
