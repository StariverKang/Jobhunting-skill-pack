# 简历叙事与证据审查方法论

## 1. 简历的基本单位

简历不是经历存档，而是面向目标岗位的证据系统。它包含四层：

1. **叙事**：候选人是谁，为什么沿这条路线成长，下一步要解决什么问题；
2. **证据**：哪些经历、项目、作品和结果证明这一叙事；
3. **翻译**：如何让 HR、业务面试官和跨行业读者以低成本理解；
4. **格式**：如何通过排序、层级、标题和密度让重点先被看到。

审查顺序固定为：候选人档次 → 目标叙事 → 证据容量 → 经历取舍 → 单段结构 → 行业语言 → 版面。

## 2. 叙事不是口号

有效叙事必须由至少两类证据支撑：持续行动、难度提升、责任扩大、作品产出、业务结果、外部选择或专业方法。叙事可以解释不完美的起点，但不能替代事实。

起步型的叙事回答“为什么值得给第一次机会”；成长型回答“为什么这条成长路线自然通向下一岗位”；冲刺型回答“为什么在多个强候选人中，这组证据最贴当前业务问题”。

## 3. 成长路线

成长不等于公司名越来越大。可观察的成长信号包括：

- 从执行单点任务到定义问题和方案；
- 从个人交付到跨团队协作或影响他人；
- 从一次性产出到流程、机制或系统；
- 从完成动作到承担指标、质量或业务结果；
- 从通用能力到特定行业、用户或技术的专业深度。

成长型候选人的编排应使这些变化可见。必要时可用相关性优先、成长线次优先、时间顺序兜底。

## 4. 问题、工具链与结果

专业经历不是“做了什么”的清单，而是一个最小业务闭环：

`问题/前置条件 + 约束与判断 + 工具链/方法 + 动作链 + 交付/结果 + 影响`

工具链不限于软件。它可以是研究方法、数据处理、沟通机制、工程组件、运营流程、设计规范、实验体系或行业标准。必须使用准确动词区分“理解、使用、配置、分析、设计、开发、部署、推动、验证”。

结果可以是业务指标，也可以是交付、采用、上线、覆盖、质量、效率、决策支持、用户反馈或外部评价。没有因果证据时，不把“参与”写成“带来”。

## 5. 两层“总—分”

第一层总述解决外行理解成本：

`背景/产品/组织是什么 + 面向谁 + 候选人的角色与目标 + 能力模块 + 总体结果`

第二层分述承载行业专业性：

`能力主题 + 问题/前置条件 + 关键判断 + 动作与工具链 + 交付/结果 + 业务影响`

冲刺型候选人的保留经历全部使用两层结构。起步型和成长型按材料密度使用：薄经历保持一个完整最小闭环，丰富经历再拆 2–4 个能力主题。

## 6. 低理解成本与高专业密度

总述要让不了解行业的人知道“这是什么、为什么做、候选人负责什么”；分述要让同行知道候选人是否真正理解流程、约束和方法。通俗不是去专业化，专业也不是堆缩写。

术语只在满足三项时使用：与目标岗位相关；与具体动作和对象相连；能帮助识别专业能力。否则翻译为普通业务语言。

## 7. 个性不脱轨

个性是可辨认的工作方式、长期兴趣、判断偏好或用户理解，不是“热爱、负责、有网感”等自评词。个性锚点应当：与目标相关、可解释、有行为证据、不会遮蔽核心能力。

可用表达包括：长期服务某类用户形成的洞察；跨学科方法如何改变解决问题的方式；个人作品如何验证对行业的持续投入；某个非标准经历如何形成目标岗位所需的稀缺视角。

## 8. 经历取舍

每段经历只能承担有限的证明任务。将经历标为：

- **支柱**：直接命中目标岗位核心问题，值得详细展开；
- **证明**：补充另一项重要能力或成长节点；
- **补充**：提供背景、个性或底部能力信号，压缩呈现；
- **删除**：重复、跑题、信号过弱或解释成本高于收益。

相似生态位的经历只保留信息增量最大的。跨行业经历保留可迁移的问题、方法和结果，压缩行业背景。

## 9. 可追问 Hook

高质量简历既自洽又不把所有故事讲完。Hook 可以是：一次取舍、一项难题、异常指标、失败后的调整、跨部门分歧、关键方法或业务洞察。Hook 应让面试官自然追问，并允许候选人继续讲完整因果链。

## 10. 标准化与自适应

标准化用于减少理解成本：统一标题、日期、层级、能力主题和数字口径。自适应用于决定讲什么：候选人档次、目标岗位、材料容量和单条密度不同，保留数量、展开深度和叙事重点必须变化。

不要用固定字数、固定经历数或固定模板替代判断。
