# 双层“总—分”结构、长度与补全边界

## 1. 结构的对应关系

一段经历由两层同时构成：

| 层级 | 简历中的位置 | 必须回答的问题 |
| --- | --- | --- |
| 第一层“总” | `工作概述` | 这是什么业务/项目，覆盖什么职责范围，为谁或什么目标服务？ |
| 第一层“分” | 2–4 个加粗主题标题 | 这段经历可被招聘方识别的核心能力/业务环节是什么？ |
| 第二层“总—分” | 每个主题冒号后的正文 | 在这个环节做了什么，卡点是什么，怎样推进，形成什么交付或观察到什么结果？ |

主题标题与正文必须前后对应：例如总述写“围绕商家后台流程、需求推进与知识库建设”，可拆成“流程运营”“需求闭环”“知识库建设”；不能另起一个没有来源的“商业化策略”。

## 2. 第一层“总”：工作概述

工作概述写 1–2 句，通常以动作开头而非候选人主语：

- `参与面向海外用户的……，负责……，围绕……推进……`；
- `负责……的需求收集、流程设计与上线协同，服务于……`；
- `围绕……业务，覆盖……、……与……，以……为目标。`

不要写“我负责”“本人参与”“这段经历主要是”。要让陌生读者立即知道业务/产品、职责范围、动作目的和工作位置；不是把公司介绍、项目愿景或任务清单堆进去。

**长度规则**：去掉 Markdown 标记和空白后，新工作概述 `>= max(80, 源概述可见字符数)`。源履历只有一句也不能压短；没有源概述时，以至少 80 个可见字符建立足够的业务颗粒度。长度没有上限，但删除同义重复。

## 3. 第二层“总—分”：主题正文

每个主题的冒号后先落一个核心句，再依实际信息密度自然串联：

`场景/对象与核心动作 → 卡点或约束（如有） → 拆解与推进链 → 方法、技术链或协作方式 → 交付、结果或后续观察`

不是每项都硬塞五个小标签；没有明确痛点时不假装有痛点。招聘简历常用的节奏是“先说负责什么，再说如何解决复杂性，最后落到输出/变化”，而不是“职责：… 方法：… 成果：…”。

- 主标题如 `**需求分析与迭代：**` 不计入长度；它后面的正文严格 `>=80` 个可见字符，目标 100–180 字。
- 每项必须有中心句，不能靠一串工具名或缩进子项凑字数。
- 允许在正文后加 1–3 个缩进子项，适用于一个主题确实含多条紧密的技术/项目链；子项仍要是完整句，且不能把另一个独立能力偷塞进来。
- 主题应覆盖不同的动作链，通常选产品/流程、内容/增长、项目协同、数据/研究、AI/自动化等 2–4 项，而非按日常杂务切块。

## 4. 起草分支

先建立每段经历的内部素材卡：

`业务与对象｜角色/位置｜职责范围｜实际动作与方面｜目标/卡点｜方法/工具｜数据/成果｜源概述长度`

### 可直接写（包括增补草稿）

只要能识别至少两个持续或可解释的动作/方面，即可生成完整结构。例如已知“整理活动数据、做周度复盘、协调内容上线”，但不知道具体工具、指标和成果时，仍可写“数据整理与复盘”“内容上线协同”两项。

资料未覆盖的方法、工具、数据口径、交付物或成果细节，可以用本行业一般可行、可替换的表达把动作链写完整。此时使用 `enhanced-draft`，并在全文末尾保留：

> 注：数据、方法论、工具等细节需要自行根据事实修正，不保证绝对正确。

这种补全不应伪造精确数字、专有系统实操、客户、任职或确定性因果结果；优先补“如何复盘、如何拆解、与谁协同、可能观察哪些口径、形成何种交付物”的通用链路。

### 必须要求补充

若连核心动作/方面都无法识别或只能得到一个不可展开的笼统表述，**不要**生成总述和主题。按经历输出：

```markdown
## [已有的经历标题]

### 缺失的动作/方面

- [缺少服务的业务、产品、用户或团队]
- [缺少持续负责的具体动作、对象和边界]
- [缺少至少第二个可独立解释的工作方面]
```

只列实际缺失项，不把数字、工具、成果当成硬性追问条件。

## 5. JD 与术语选择

有 JD 时，提炼 3–5 个能力主题，用其决定主题排序、术语和展开比例；不把 JD 中的职责、指标或工具写成候选人已做过的事实。无 JD 时按业务影响、职责密度与读者理解顺序组织。

从 [lexicon.md](lexicon.md) 选术语时，先判断 `行业域 + 职能域 + 已知动作`。每个术语要落到准确谓词、对象和交付；跨行业缩写首次出现时加普通业务解释。用“围绕……框架”“按……思路”描述通用补全，避免把没有来源的专有工具写成既成实操。

## 6. 完成前自检

1. 工作概述是否没有“我/本人”，且足够长、不短于源概述？
2. 是否有 2–4 个不同主题，且标题与总述职责范围对应？
3. 每项主题正文是否有核心句，且标题外不少于 80 个可见字符？
4. 是否自然写出了卡点（如有）、行动链、方法/技术链和交付/结果，而不是套标签？
5. 自动补全时是否只留一次固定末尾提示，且没有因数字/工具缺失而中断？
6. 只有在动作/方面确实不足时，才输出“缺失的动作/方面”？
